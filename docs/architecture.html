Model Cartographer

Active discovery of LLM capability frontiers. Latent tasks are the controlled experimental object; natural language is a rendered surface; the failure decomposition engine is the centerpiece. Design v3 — locked.

Component board

One card per buildable unit, in dependency order. Each card is a contract: what goes in, what comes out, and the invariants that must never break. Work top-left to bottom-right.

phase 0 · validation

synthetic harness

Fake "models" with hand-written failure rules — single-factor, planted interactions, noisy variants. Implements the same client interface as the real execution layer.

in rendered tasks
out pass/fail per rule + injected noise
  • Decomposition must recover planted rules before any real run is trusted
  • Must also NOT find interactions where none were planted
phase 0.5 · foundation

schemas + results store

Canonical experiment record: latent params, realized dim values, rendering id + mode, mutation lineage, model, verdict, tokens, cost, latency, seed.

in every event in the system
out queryable history for all analysis
  • Realized dimension values logged for every task, not just the mutated knob
  • Cost fields present from day one
phase 1 · task system

latent world generator

One compositional generator: entities, objects, events, beliefs, timestamps. All five launch dimensions fall out of one world model.

in dim params + seed
out latent task + ground-truth answer
  • Latent representation is the sole source of truth
  • Dims: entity/state · temporal/causal · coreference · distractors · context length
phase 1 · task system

mutation engine

Controlled transformations of latent variables; surface is re-rendered afterward, never edited directly.

in latent task + factor spec
out mutant latent task(s)
  • Mutations edit latent vars only
  • Side effects on other dims are measured and logged, not assumed zero
phase 2 · task system

template renderer + verifier

Deterministic latent→text rendering (trusted baseline mode) and deterministic verification against the latent answer. No LLM judge anywhere.

in latent task / model response
out prompt text / pass–fail verdict
  • Accidental ambiguity is a bug: rewrite, or define "indeterminate" as the expected answer
  • Verifier reads truth from latent task only
phase 2 · runs continuously

real-model pilot

~50 tasks through Nano/Super/Ultra the day rendering works. Validates parsing, refusals, rate limits, real costs, and that difficulty knobs actually span easy→hard.

in rendered tasks
out validated execution client + cost calibration
  • Pilot code graduates into the campaign client — not throwaway
phase 3 · centerpiece

failure decomposition engine

Given a failure region: test single factors, then pairs, higher-order only when justified. Finds the minimal factor set that reproduces the failure.

in failure + budget
out structured hypotheses (factors, direction, seeds, evidence)
  • Never collapse results into one scalar difficulty
  • Output format is machine-confirmable by phase 7
  • Validated on synthetics before touching real data
phase 4 · critical gate

nemotron renderer + fidelity gate

LLM rendering as a variation layer over the same latent task. Every rendering passes round-trip extraction; mismatches are rejected and regenerated.

in latent task
out verified natural-language variant
  • Fidelity checks are mandatory, never sampled
  • Rejection rate logged per dimension
  • Renderer tier ≠ subject tier (self-contamination guard)
  • LLM-rendered results that contradict template-mode results are flagged, not averaged
phase 5 · probe system

adaptive scheduler

Wave-based dependency queue: coarse exploration → boundary refinement → interaction probes → confirmation batches. Consumes frontier estimates each generation.

in current estimates + budget
out next parallel wave of experiments
  • The estimator→scheduler feedback edge must exist — without it this is a grid sweep
  • Stop rules: boundary localized (estimation) vs. hypothesis survives ablation (investigation)
phase 5 · infrastructure

execution layer

The single path to models: Serverless Jobs fan out waves; Token Factory serves Nano/Super/Ultra. Retries, rate limiting, and cost accounting live here once.

in wave of (task, model) requests
out raw outcomes → results store
  • Ablation and scheduler share this path — no second API client anywhere
phase 6–7 · analysis

campaign + confirmation

Full sweep across three tiers, then candidate hypotheses re-tested on held-out fresh seeds and fresh renderings, with effect sizes, intervals, and multiple-comparison control.

in structured hypotheses
out confirmed findings with uncertainty
  • Confirmation seeds are never seen during search
  • Report effect sizes, not pass/fail verdicts
phase 8–9 · products

atlas · analyst · router

Atlas visualizes failure geometry and cross-model differences with cost overlays. Evidence Analyst (Nemotron Ultra) writes the capability diagnosis from stored results. Router demo derives a tiering policy from measured frontiers.

in results store + confirmed findings
out demo URL · report · routing receipt
  • Analyst narrates evidence; it never invents findings
  • Router is a downstream demo, never the headline

Build order

Dependency sequence, not a calendar. The pilot forks at phase 2 and runs alongside everything after it.

0synthetic→ 0.5schemas→ 1generator→ 2render+verify ⑂ pilot→ 3decomposition→ 4LLM render gate→ 5scheduler+jobs→ 6campaign→ 7confirmation→ 8atlas→ 9submission

Cut order under pressure

  1. Dimensions: 5 → 3 (keep state, temporal, distractors)
  2. Router demo
  3. Atlas polish
  4. Nemotron rendering (template mode still yields valid results)

Never cut: synthetic harness · fidelity gate · confirmation · pilot.
