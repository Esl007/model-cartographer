# Can Read, Can't Repair

### A deterministic capability map of Gemma 4 as a coding agent — six executable task worlds that locate its boundary in code change, perspective retrieval, and turn-by-turn acting, and retract their own headline finding along the way

## Abstract

Where exactly does a strong small coding model stop being capable? We map `gemma-4-31b-it-qat-w4a16-ct` — the checkpoint this competition mandates — with Model Cartographer, an instrument that generates tasks from latent structures with executable ground truth, so no LLM ever judges an answer. Six task worlds probe narrative state and belief, tool planning, interactive execution, code tracing, code repair, and multi-file repository repair; an adaptive engine escalates difficulty, gates every failure through resampling, attributes causes by answer-key-preserving ablation, and confirms boundaries on fresh seeds. The map is sharply uneven. Gemma 4 reads code essentially perfectly (~700/700 compact tracing trials, including counterfactual dialects and misleading comments) yet breaks at repairing a single injected bug when hidden checks exist (35% pass), and at repository scale it finds the buggy file in 23/23 episodes while fixing the cause in 5/23 — most failures overfit the visible test, down to inserting magic constants. Belief tracking fails by substituting reality for a person's perspective (12/30 under conflict); restating witnessed facts rescues it (27/30, Holm-corrected p=1.6×10⁻⁴) while merely emphasizing them does not (p=0.69) — a retrieval failure, not an attention failure. Our instrument also caught itself: a fresh-seed-replicated "ticket fabrication" finding dissolved when we discovered the text tool protocol executed entire blindly-written trajectories; we retract it by pre-registered rule and report the survivor — Gemma 4 plans whole episodes without awaiting results. We release the instrument, the repository-repair benchmark generator, and all trajectories.

## 1. Introduction

Benchmarks tell us *that* a model fails; building reliable agents requires knowing *what* ran out — knowledge, retrieval, perspective, or the ability to change code without breaking it. The distinction is causal, and real-repository benchmarks cannot settle it: tasks vary in a hundred properties at once, ground truth is partial, and training-set contamination shadows every success.

We take the opposite route. Every task is generated from a latent structure — a story's event log, a tool-world state machine, a program's syntax tree, or a multi-file repository rendered from a single program — so the correct answer is computed by simulation or execution, difficulty is a set of controlled dials, and fresh uncontaminated tasks cost nothing. We then ask one question across six worlds: **when the plausible answer and the evidenced answer disagree, which one does the model produce — and which minimal intervention flips it back?**

Applied to the competition's own checkpoint, this yields a map with an unexpected shape. The model's comprehension is near-ceiling: it traces 20-step dependency chains, obeys declared counterfactual language rules, ignores lying comments, and declines impossible tasks. Its boundary lies in three specific places: **changing** code it demonstrably understands (it patches symptoms and overfits visible tests), **retrieving carried perspective** (it answers where an object *is*, not where a person *believes* it is — unless the witnessed facts are restated at the decision point), and **acting turn-by-turn** (given a free-form tool protocol, it writes its entire imagined trajectory, fabricated results included, in one message). Each boundary comes with a measured, causally attributed intervention, which is what makes the map useful for building the agent rather than merely grading it.

A secondary contribution is methodological. The instrument's discipline — resample gates, pre-registered hypotheses, and a public register of ten retracted or corrected claims — caught our own headline finding being an artifact of the harness, not the model. We believe the retraction (§3.4) is as informative as any result we kept.

## 2. The instrument

**Six worlds, one rule.** Model Cartographer generates tasks in six provinces: (I) narrative world-model — stories of moves and observations, querying object state, event order, or a person's *belief*, with per-agent witness tracking; (II) single-shot tool planning over a devops state machine with BFS-verified plans; (III) interactive execution, one tool call at a time with returned values to carry; (IV) code tracing — predict a generated Python program's output, verified by our own interpreter (differentially tested against CPython on thousands of programs, zero mismatches); (V) code repair — one injected bug, a failing visible test, hidden checks; (VI) repository repair — the same latent program *partitioned into modules*, imports derived from call edges, the failing test in a different file than the cause, with tools mirroring this competition's harness (`read_file`, `search`, `edit_file`, `run_tests`, `get_code_neighbors` over the constructed call graph). The one rule: **no LLM anywhere in generation, mutation, or verification.** Model-written code is parsed into a restricted AST and executed in our interpreter on hidden inputs; nothing a model outputs is ever `exec`'d.

**The engine.** Difficulty escalates along rays (ramp → bisect → logistic boundary → factor decomposition → fresh-seed confirmation). Every failure entering analysis is resampled three times at temperature 0 — necessary even for dense models: we measured first-request-vs-warm prefix-cache nondeterminism flipping verdicts. Causes are attributed by *answer-key-preserving ablations* (mutate the task's surface, assert the answer unchanged, re-run) under Holm–Bonferroni correction. Interventional hypotheses are pre-registered with fixed statistics before any live record. A reproducibility certificate (compact ≤12 decisions; resample-stable; fresh-seed-confirmed; factor-attributed) gates what may be called a breaking point. Validity is established before spend: planted fake agents, each scripted with one weakness, must fail exactly on their mechanism, and a perfect agent must never fail.

**Why believe the generators are hard enough?** The same instrument breaks other models on these mechanisms: Gemma 3 27B degrades to 57% on state tracking, 18/42 on semantic code traps, and declines 0/16 impossible tasks; Nemotron Nano breaks at 13-call look-alike plans. When Gemma 4 passes, it passes tests that demonstrably cut its neighbors.

**Protocol-artifact discipline.** Small-model evaluation is dominated by instrument errors wearing model-failure costumes. Our register logs ten: token caps that fabricate difficulty-correlated "declines"; a provider silently dropping the `tools` field; campaigns fired at cold endpoints scoring startup timeouts as failures; a `read_file` layout whose separator the model copied into edits (fixing it *lowered* the pass rate — broken edits had been blocking the model's own bad patches); and the protocol flaw in §3.4. Every claim below survived this gauntlet or is reported with its correction.

## 3. Results

All results: `gemma-4-31b-it-qat-w4a16-ct` served via vLLM on one L40S, text tool protocol, temperature 0. Total compute for the full map: under 15 GPU-hours and ~$0.70 of tracked token cost — a frontier-quality capability map on everyday hardware, matching the competition's own thesis.

### 3.1 Reading is solved; changing is broken

Across ~700 compact tracing trials — six semantic trap families (aliasing, negative modulo, late binding, shadowing, shared defaults, off-by-one ranges), stacked list semantics, computed `while` loops, 20-deep update chains, adversarially selected programs, misleading comments, look-alike variable names, and 143 meaning-preserving rewrites in a dedicated failure hunt — Gemma 4 QAT passed everything. This is a *certified* null: the identical tests break Gemma 3 and planted fakes. (Scope honesty: a cross-check later found one program family, the 18-statement repair-world shape, where tracing does fail 5/5 resample-stable; the null is narrowed to the tested distribution, not withdrawn.)

Repair of the *same class of programs* collapses. One injected bug, a failing visible example, four hidden checks: 0/5 on the first ray, 35% (7/20) on fresh-seed confirmation after all protocol artifacts were rescored. Read-vs-write pairing makes the dissociation explicit: in the pooled runs the model correctly traced the buggy program's output yet still failed to repair it in 12 episodes, against 9 where tracing and repair both succeeded. The failure modes are not random: `wrong_site` edits (plausible lines that aren't the bug), and — most diagnostic — *visible-test overfitting*. In one reproducible case the model made the **correct fix**, miscomputed its own function's output, and then added `depth += 15  # Offset to reach 100`: fudging a constant to force the shown example while breaking every hidden input. It optimizes "make the visible test pass," not "repair the cause."

### 3.2 Repository scale: finds the file, patches the symptom

Province VI splits the same latent program across 1–12 files; the failing test never lives in the causal file. Navigation turns out to be the *solved* part: the model read the bug's file in **23/23** episodes, median three tool calls. It then fixed the cause in **5/23 (22%, CI 10–42%)** — statistically indistinguishable from its single-file repair floor (pass rates 2/8, 2/8, 1/7 at 1, 4, 8 files). The failure signatures replicate §3.1 at scale: `visible_fixed_hidden_broken` (7/18 failures) — e.g., patching the *call site* in `scoring.py` with `+ 106` when the bug lives in `reporting.py` — plus wrong-file and wrong-line edits. Pre-registered H3 (visible-test overfitting reappears at repo scale) confirmed: 27% of failures, against a 10% bar.

Two further pre-registered results. **Graph tools went unused**: with `get_code_neighbors` available over a perfect constructed call graph, the model called it **0 times in 15 episodes** (167 `read_file` calls, 2 `search`). Median calls-to-reach-the-causal-file: 7.0 with the tool vs 6.5 without (Wilcoxon p=0.80, 12 pairs). The hosts' graph affordances are inert for this model unless an agent scaffold forces them — a directly actionable, and testable, configuration decision. **No navigation cost was measurable** at this sample: the bottleneck is the change, not the search.

### 3.3 Perspective fails by substitution — and restatement, not emphasis, repairs it

On false-belief stories ("where does A *think* the object is?"), Gemma 4 QAT scores 56%, barely above Gemma 3 (49%) and far below Nemotron Nano (90%), with one dominant error: it answers the object's **true** location. Two controls pin the mechanism. First, the *trivialized* variant — A actually witnesses the final move, so belief equals reality — is passed at ceiling. Frontier models famously fail trivialized puzzles by template-matching (GPT-4o drops 75→20% on unpuzzles [5]); Gemma 4 shows the mirror pattern, so its failure is not template recall. It genuinely lacks robust perspective retrieval and defaults to the world state it tracks flawlessly.

Second, a paired intervention grid on 30 seeds (pre-registered; McNemar, Holm-corrected): with prior and evidence agreeing, 30/30; under conflict, 12/30; **restating the agent's witnessed events immediately before the question: 27/30 (p=1.6×10⁻⁴)**; merely *emphasizing* the same sentences in their original position: 15/30 (p=0.69). The information was always present; what fails is retrieval across the story, and salience-at-the-decision-point — not formatting — is the lever. On the same grid, misleading code comments cost nothing in any condition, including when the lie is typographically shouted: evidence the model holds *in view* reliably beats its priors; evidence it must *carry* does not.

### 3.4 A pre-registered retraction, and the finding that survived

Our strongest early result said Gemma 4 could not carry an opaque 8-character ticket across even one tool call without *fabricating* a pattern-plausible substitute (~40% of episodes; fresh-seed replicated; "restate the ticket" rescued 6/6 failures). A cross-cutting campaign then failed its own sanity condition and exposed the cause: our free-form text protocol executed **every** call in a model message — and Gemma 4 writes entire imagined trajectories in its first message, invented tool results and all. 435 of 531 historical episodes had ≤2 turns; the model often never saw the ticket it "failed to copy."

We re-measured under a turn-disciplined protocol (one call per turn; stop at fabricated output blocks) with a decision rule fixed in advance. Fabrication vanished: 33/33 and 31/31 on the original rays to 16-call plans, 50/50 across the intervention grid, zero invalid tickets, median 11–15 turns. **We therefore retract the fabrication claim as stated** (register entry X10; originals preserved with addenda). The survivor is a different, equally consequential finding: **blind-trajectory planning**. Under a permissive protocol this model does not act-observe-act; it hallucinates the whole episode — while Gemma 3, under the identical protocol, worked turn-by-turn. For agent builders this is a harness-design result: free-form multi-call formats silently convert a planning disposition into fake execution; enforced turn boundaries fully recover value-passing competence (and earlier, feedback visibility rescued look-alike tool binding from 1/14 to 12/17).

### 3.5 What this model is *not* missing

Equally load-bearing are the certified non-failures: object state and event order at 100% through 30-step chains (Gemma 3: 57%); declared counterfactual dialects obeyed at ceiling (so the priors *can* be overridden by in-view rules); GSM-NoOp-style distractor clauses [2], misleading comments [7], and premise-order effects [3] — all famous frontier failure modes — do not transfer; impossible tasks are declined at balanced accuracy 0.875 (Gemma 3: 0/16 declines); transient tool faults are recovered 40/40; and behavior is task-deterministic (pass¹=pass⁵=0.625 over repeats, zero flaky tasks), so its unreliability is a stable property of tasks, not sampling noise. The capability profile is not "small model, uniformly worse": it is *differently shaped* — more robust than frontier models to textual misdirection, weaker at perspective and code change.

## 4. What the map prescribes for the agent

Each boundary pairs with a measured intervention, directly applicable to this competition's harness: (1) **force verification by execution** — never let the model satisfy a visible expected value it can constant-match; its dominant repair failure is exactly that; (2) **restate carried facts at the point of use** — witnessed events, symbol inventories, opaque identifiers — rather than emphasizing them at origin (p=1.6×10⁻⁴ vs p=0.69); (3) **enforce turn discipline** in any text tool protocol, or the model will fabricate its own observations; (4) **force or drop graph tools** — unforced, they are dead weight for this model; (5) exploit its honest refusals and determinism: it declines the impossible and fails reproducibly, so routing and retry policies can be planned rather than gambled.

## 5. Related work

SWE-bench and successors [1] evaluate repair on real repositories, where contamination and uncontrolled difficulty preclude causal attribution; our generated-repository world trades realism for exactness and pairs every repair with a tracing control. Capability-vs-elicitation analyses [9] and budget-aware agent studies [10] motivate measuring *mechanisms* rather than scores. Our belief results connect to SimpleToM's knowledge-vs-use gap [6] and adversarial ToM generation [4], with the trivialized-puzzle control adapted from [5]; our distractor and comment nulls test transfer of GSM-Symbolic [2] and CodeCrash [7]; multi-turn degradation and premature commitment echo [8], which our blind-trajectory finding sharpens into a protocol-level mechanism. The instrument's discipline draws on adaptive evaluation [11] and pass^k reliability reporting [12]. To our knowledge, the combination — executable ground truth across six task families, answer-key-preserving causal ablation, pre-registered interventions, and a public retraction register — has no direct precedent in agent evaluation.

## 7. Limitations

Our worlds are synthetic: functions are small, repositories are rendered from single programs, and realism is traded for ground truth — the §3.1 scope-narrowing shows the tested distribution matters. Results are one checkpoint (quantization effects are confounded with model generation; the bf16 contrast is future work) under the text tool protocol; within-model paired comparisons are unaffected, but cross-model absolute numbers inherit protocol differences. Several VI results are first-run (n=10–23) with wide intervals; the belief grid and repair floor carry confirmation-grade evidence, the graph-tool null does not yet. Serving nondeterminism bounds reproducibility of any single trajectory; all paired claims carry resample gates.
